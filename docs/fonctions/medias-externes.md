### Doodles du site (case « Recuperer les medias », onglet Affichage)

Recupere les fichiers deposes sur le site Casual Ravers (bucket Supabase Storage public `doodles` : PNG / JPEG, 5 Mo max) et les affiche **par-dessus
la projection**. Desactive par defaut.
- **Configuration** : `~/.audio2wave/depot.json` = `{"url": "https://<projet>.supabase.co", "anon_key": "..."}` (jamais dans le code ni versionne). Absente
  ou incomplete : la case reste active, le statut (ligne d'etat de la GUI) dit ce qui manque ; la config est relue a chaque tour tant qu'elle manque.
- **Reglage `doodle_on`** : portee `state` (ni sauve par P, ni dans l'auto-sauvegarde, ni presets overlay / fond, ni scenes, ni memoires de masters) ;
  PANIQUE n'y touche pas (comme le logo et le texte). Decocher arrete l'interrogation ; les doodles deja affiches finissent leur fondu.
- **`core/doodles.py`** (pur) : `parse_config` / `load_config`, `list_request` (POST `/storage/v1/object/list/doodles`, `sortBy created_at desc`, `limit` 100 :
  les plus recents d'abord, sinon passe 100 fichiers les nouveaux n'apparaitraient plus), `download_url`, `parse_listing`, `Seen` (`arm` a l'activation =
  l'existant est memorise sans etre affiche ; `fresh` du plus ancien au plus recent ; `mark`), `check_download` (vide, > 5 Mo, signature PNG / JPEG : le
  suffixe ne prouve rien), `check_size` (<= 4096 px), `place` (rectangle toujours entierement dans le cadre, hauteur `max_height` de l'ecran, ratio garde ; `height_for(part transparente)` : une photo (opaque) `MAX_HEIGHT_FRAC` 45 %, un texte / dessin detoure (plus de `CUTOUT_SHARE` 10 % de pixels transparents) `TEXT_HEIGHT_FRAC` 30 % ; `avoid` = rectangles des medias deja la : positions tirees dans un endroit libre (marge `GAP`), taille reduite jusqu'a 55 % si la place manque, sinon le moins de recouvrement : les medias ne se superposent plus, les textes restent lisibles), `alpha` (fondu 1,5 s / palier / fondu 2 s sur 15 s), `Wall` (`MAX_VISIBLE` = 3 visibles au plus, le plus ancien part), `poll_once` (un tour sans fil : reseau injecte).
- **`engine/doodle_feed.py`** : `DoodleFeed` = fil d'arriere-plan (tick toutes les 250 ms, interrogation toutes les 5 s, timeout 6 s), jamais dans le fil GL
  ni Tk. Une erreur reseau est dite dans le statut (`status["doodles"]`), journalisee **une seule fois** (`sessionlog`) et reessayee au tour suivant ; un
  telechargement en echec n'est pas marque « vu » (reessai), un fichier invalide l'est. Decodage Pillow (`decode` : taille lue avant tout decodage,
  `exif_transpose` pour les photos, `_premultiplied` comme le logo) puis `Session.doodle_queue`. Demarre par `run_app` (le fil dort tant que la case est decochee).
- **Rendu** (`Renderer.add_doodle` / `_draw_doodles`) : la boucle GL vide la file a chaque image. Chaque doodle visible relance la **passe LOGO de `scene.frag`** (`u_pass` 1) avec SA texture et SON rectangle a la place
  de ceux du logo, melangee en alpha premultiplie sur la couche du logo (`layer_fbo`) : il recoit donc **tout ce que recoit le logo** : fonte acide, cellules, contour lumineux, opacite / master overlay, puis (dans `post.frag`) les effets par couche
  (ondulation, onde de choc, aberration, glitch ; lies au fond ou propres au logo, `fx_link`), l'aura holographique (calculee sur l'alpha de la couche ; centree sur le logo), la traînee et la composition (symetrie, pixelisation, teinte, strobe).
  `u_layer_on` (post.frag) garde la couche active meme sans logo. Pas de shader dedie (doodle.vert / doodle.frag supprimes). Liste vide = aucune passe (aucun cout) ; au plus 3 doodles = 3 passes plein cadre en plus.
  Les doodles arrives projection fermee sont jetes (`Projection.start`). 
  **Animation** (`core.doodles.pose`, `Wall.posed`) : apparition en « pop » (echelle 0 -> 1 avec depassement de ~9 %, rotation de ~17 degres qui se redresse en balancant, 0,9 s), palier droit, disparition (gonfle un instant, rapetisse en pivotant, 0,9 s) ; le sens de rotation alterne d'un doodle a l'autre. Fondus d'opacite courts (0,4 s / 0,7 s). Le shader du logo sait pivoter (`u_logo_cs` = cos, sin ; sin = 0 pour le logo, qui reste droit) : fonte, cellules et contour suivent la rotation.
- `check_gl.py` (`check_doodles`) : logique pure, fil avec faux reseau et horloge injectee, **vrai serveur HTTP local** (en-tetes, corps, 404, serveur
  injoignable), rendu hors ecran (taille, ratio, position, sens, alpha premultiplie, fondu, limite de 5, expiration, panique), reglage hors presets /
  sauvegarde, case de la GUI.
- **QR code permanent** (case **QR sur la projection**, onglet *Affichage*, a cote de « Recuperer les medias » ; champ d'adresse + menu du coin) : pour que le public trouve le site et depose ses medias sans qu'on l'explique. Reglages `qr_on` (0), `qr_url`, `qr_corner`
  (`bas droite` par defaut, `bas gauche`, `haut droite`, `haut gauche`), `qr_size` (0,18 = cote en fraction de la hauteur, sans curseur) : portee `device` (sauves avec P et l'auto-sauvegarde, **jamais** dans un preset, une scene ou la PANIQUE ; une installation, pas un look).
  `Renderer._draw_qr` est appele **tout a la fin de `draw`**, apres la composition et la trainee : le QR est droit, opaque (noir sur blanc, marge de 4 modules comme la norme), sans symetrie, pixelisation, teinte, strobe ni deformation, donc toujours lisible par un telephone.
  Taille = nombre ENTIER de pixels par module (bords nets, `NEAREST`), marge de 2 % de la hauteur ; adresse vide ou trop longue (213 octets) = rien dessine, la GUI le dit dans le statut. La texture est gardee tant que l'adresse ne change pas (`core.qrcode.to_gray` fait l'image).
  `check_gl.py` : `check_qrcode` (image), `check_qr_projection` (pixel pour pixel dans les quatre coins, reste de l'image intact, aucun effet ne le touche, coupe / vide / trop long, taille).

### Enregistrement video + audio (`core/recording.py`, `engine/recorder.py`, onglet *Rec*, touche E ; issue #140, spec `docs/plans/2026-11-13-enregistrement-video-design.md`, plan `-plan.md` avec son journal d'ecarts)

Un bouton **REC** (barre des scenes, tout a droite, a la place de l'ancien PANIQUE ; largeur fixe, « ■ mm:ss » pendant l'enregistrement, grise sans projection) ou l'onglet *Rec* produit UN MP4 pret a poster (contenu maison, pas en soiree) : H.264 yuv420p + AAC 320 k stereo 48 kHz, bt709, faststart. L'audio est le son brut de l'entree de la carte son (`SoundDeviceInput.tap`), pas la capture du rendu. Pas de format de montage : l'utilisateur ne fait que couper debut / fin et etalonner.
- **Reglages** (portee `device`) : `rec_format` (`vertical` 1080x1920 par defaut, `vertical_hd` 720x1280, `horizontal`, `carre`), `rec_fps` (30 par defaut, 60), `rec_encoder` (`libx264` veryfast crf 17, ou `materiel` = nvenc / amf / qsv s'il est liste ET passe un test d'une image), `rec_delay_ms` (40), `rec_dir` (`~/Videos/casual-overlay`). Nom du fichier `casual-AAAA-MM-JJ_HHhMMmSSs.mp4` (suffixe -2, -3).
- **`core/recording.py`** (pur) : formats, `frames_due` (images dues a cadence constante : un rendu en retard DUPLIQUE des images, la duree reste juste), `fit_rect`, `output_name`, commandes ffmpeg (`video_command`, `mux_command`), `choose_encoder`, `peak_db`, `drop_warning`. `explain.rec_status_text` / `rec_panel` = voyant et etat du bouton.
- **`engine/recorder.py`** : `RawAudioWriter` (file bornee, ne bloque jamais le callback audio ; un trou de plus de 40 ms est comble par du silence, fin de fichier comprise), `Recorder` (ffmpeg rawvideo sur stdin), `RecordingControl` (branche dans `engine/projection.loop`). Commandes `rec` / `rec_start` / `rec_stop`, voyant `s.status["rec"]`, fin `s.status["rec_done"]`.
- **Pieges** : (1) **un seul `draw` par image** : `Renderer.draw` integre les animations a chaque appel, donc l'image enregistree est dessinee UNE fois dans un FBO a la taille de l'enregistrement, puis recopiee dans la fenetre (`Renderer.blit_fit`, bandes noires) ; dessiner deux fois accelererait tout. **Vertical / carre = fond ROGNE au centre** (pas ecrase) : pendant un enregistrement `Renderer.video_cover` fait lire la texture du fond (flux audio2wave, video de fond, Snap / Ridge / Sphere) par `core.recording.cover_uv` (`u_video_crop` dans `scene.frag`) ; logo, motifs generes et effets sont deja dessines a la taille du cadre ; hors enregistrement rien ne change. (2) **lecture synchrone** (`fbo.read`) : l'asynchrone ajoute une image de retard qui fausserait la synchro ; pas de multi-echantillonnage (passe finale plein cadre). (3) **synchro** : le delai est du silence reel ajoute au debut du son (`adelay`), pas `-itsoffset` (perdu a l'ecriture du MP4) ; un delai negatif = `-ss` ; `-t` coupe a la duree de la video. (4) **bt709** par `-bsf:v h264_metadata=...` (les options `-color_*` seules laissent `unknown`). (5) deux temporaires (`*.video.tmp.mkv`, `*.audio.tmp.raw`) assembles a l'arret SOUS UN NOM PROVISOIRE puis `os.replace` : jamais de fichier incomplet sous le nom final ; assemblage dans un fil (`close()` l'attend) ; en cas d'echec les temporaires sont gardes. (6) changer l'entree audio ou un disque presque plein (< 200 Mo, avertissement a 2 Go) arrete l'enregistrement. (7) le garde-fou GPU (`PerfGuard`) ne s'affiche pas pendant l'enregistrement (il compare au budget 60 Hz). La PANIQUE n'arrete pas l'enregistrement. Fermer la projection l'arrete proprement.
- **Suites de la revue** : le delai audio effectif = `rec_delay_ms` moins `sync_lead_ms` (`effective_delay_ms`, peut etre negatif : le fichier n'a pas de latence d'affichage) ; encodeur materiel : debit impose (`hardware_bitrate`) et liste / essais gardes pour la session (`_ENCODER_CACHE`) ; arret robuste (encodeur fige tue, fil audio en erreur vide sa file), dossier invalide = message, assemblage dans un fil non daemon, double clic ignore (0,6 s). **Connus, non traites** : le comblement des trous audio ajoute du silence sans jamais en retirer (gigue des callbacks / derive d'horloge : ~40 ms toutes les 7 min sur une carte lente) ; apercus de scenes et securite GPU pendant un REC lisent la fenetre (bandes noires) et comparent `gpu_ms` au budget 60 Hz ; ffmpeg qui meurt en cours = pas de MP4 (le .mkv partiel est garde) ; HUD (H) et QR sont enregistres dans le fichier.`n- **Mesures** (poste de dev, bout en bout avec vraie fenetre et vrai micro) : 1080x1920 a 30 images/s, 180 images pour 6 s, 2 doublons ; 720x1280 : AAC stereo 48 kHz de 6,000 s ; synchro mesuree dans le fichier (horloge simulee) < 60 ms.
- `check_gl.py` : `check_recording`, `check_recorder_audio` (dans `PURES`), `check_recorder` (ffmpeg reel, horloge simulee), `check_recording_render` (contexte standalone, `GROUPES["moteur"]`), `gui_rec_steps`.
- **Non verifie** : vraie carte son externe, GPU de la soiree / du poste final (doublons a 30 et 60 images/s, encodeur materiel), delai de 40 ms (a calibrer avec `tools/calibrer_avance.py`), acceptation et normalisation du son par TikTok / Instagram.

### Telecommande telephone (`core/remote_auth.py`, `core/remote_state.py`, `core/qrcode.py`, `engine/remote.py`, `gui/gui_remote.py`, `gui/remote/`)

Petite page web servie par le processus (serveur `http.server` dans un fil, sans dependance) pour piloter depuis un telephone sur le Wi-Fi local. Plan et decisions : `docs/PLAN_VJ_REMOTE.md`.
Case **Telecommande telephone** (onglet *Affichage*, reglage `remote_on`, portee `state` : decochee a chaque lancement) ; bouton **QR / code...** ouvre la fenetre du QR (`core.qrcode`, Python pur, versions 1 a 10, niveau M, verifie par OpenCV et un decodeur de relecture), de l'adresse et du code a 6 chiffres.
- **Securite** (`core/remote_auth.py`, pur, temps injecte) : pairs d'un reseau PRIVE seulement (403 sinon), en-tetes Host et Origin verifies (DNS rebinding), jeton d'activation (fragment `#k=` du QR, jamais envoye au serveur dans l'URL) ou code a 6 chiffres echange contre un **jeton de session** (`Authorization: Bearer`, pas de cookie) ; **un seul telephone** : une connexion valide revoque l'ancienne (le flux SSE de l'ancien recoit `bye`) ; 5 essais rates par minute puis blocage 5 min ; 30 commandes/s ; corps <= 4 Ko, JSON, Content-Type exige ; CSP stricte, aucun chemin libre (table `STATIC`). Commandes = **liste blanche** `COMMANDS` (types et bornes verifies avant le moteur). **Pas de PANIQUE, pas de tap tempo** (decision de l'utilisateur). HTTP clair, jamais expose hors du reseau local (dit dans la fenetre du QR).
- **Etat** : `build_state` (dict, `v` = 1) publie par le pont a 5 Hz au plus ; SSE sur `/events` lu cote page par `fetch` + flux (EventSource ne sait pas envoyer d'en-tete : ecart volontaire au plan), `ping` toutes les 15 s, un seul abonne.
- **Pont** (`gui_remote.install`) : le fil HTTP ne touche NI Tk NI glfw ; il pose les commandes validees dans `s.remote_requests` (file) que le fil Tk execute toutes les 100 ms avec les gestes existants (`apply_entry`, `vj_toggle`, `vj_advance`, `back_scene`, `toggle_scene_lock`, `gl.strobe_press/release`, `start_build` / `do_drop`, memoires de masters, `do_one`, texte du logo). Le Verrou refuse tout de suite scene / suite / retour (409 + message). **Randomizer** (boutons `Randomizer` et `Tirer`, commande `random`) : le premier active l'ordre Full Randomizer du set, lance le VJ s'il ne tourne pas et tire tout de suite (rappuyer revient a l'ordre normal ; `vj.random` dans l'etat allume le bouton), le second est « Tirer maintenant » ; refuses sous Verrou. **Sauver la scene** (bouton de l'onglet SCENES, commande `save`) : met a jour la scene active (`capture_scene_now`, comme le clic droit > Mettre a jour) ; si la scene active n'est pas dans la bibliotheque (tirage du Full Randomizer, rien d'actif), enregistre une nouvelle scene `Remote HHhMM`. **Strobe maintenu** : la page renvoie « appui » toutes les 500 ms ; sans nouvelles pendant 1,5 s (telephone perdu, ecran verrouille) ou serveur arrete, le pont relache le strobe.
- **Apercu** (facultatif, coupe par defaut, `POST /api/preview`) : le pont demande une capture reduite (480 px) au fil GL au plus toutes les 5 s, jamais si la projection est fermee ni si `gpu_ms` depasse 80 % du budget d'une image (note affichee sur la page).
- **Page** (`gui/remote/`, JS sans framework ni style en ligne, < 150 Ko) : onglets SCENES / MACRO / BOUM / INFOS ; Reactivite et Effets en deux grands curseurs verticaux ; Montee puis Drop (un meme gros bouton : un appui monte, l'appui suivant lache le drop) ; ecran garde allume (Wake Lock) ; installable (manifeste + icone).
- **Fiabilite en salle** (page) : le flux d'etat est surveille (`lastEvent`, ping serveur toutes les 15 s) ; sans nouvelles pendant 20 s, ou au retour au premier plan / retour du reseau, la page rouvre le flux avec la session deja ouverte (une tentative sans reponse est refaite apres 8 s) et un **bandeau rouge « PC INJOIGNABLE »** clignote tant que le lien n'est pas revenu. **Drop a confirmer** : pendant une montee, le 1er appui arme le bouton (« REAPPUIE = DROP », 2,5 s), le 2e lache ; case « Confirmer le drop » de l'onglet INFOS (retenue pour la session, sessionStorage). **Voyants** : puce « MONTEE nn % » dans l'en-tete (fixe, tous onglets) a cote du BPM et de la phase. **Apercu** : visible en petit sur l'onglet SCENES, demande d'office une fois par session (sauf coupe a la main) ; l'ordi le met en pause seul si le GPU est charge. **Vignettes** : chaque scene de l'etat porte `t` (nom du JPEG d'apercu de `scenes.PREVIEW_DIR`, "" = aucun) ; la page recupere `GET /thumb/<rang>.jpg` (jeton de session exige, un nom de fichier simple seulement, 300 Ko au plus) une a la fois et les garde en blob (CSP : `img-src 'self' blob:`).
- Variables d'environnement pour les tests : `CASUAL_REMOTE_HOST`, `CASUAL_REMOTE_PORT` (0 = port libre).
- `check_gl.py` : `check_remote_auth`, `check_remote_server` (vrai serveur local), `check_remote_page`, `check_qrcode` (pures), `x_remote_bridge` (GUI : vraies requetes HTTP, Verrou, strobe relache seul).
- Lecons : un QR faux peut cacher un bug de zigzag derriere la correction d'erreur Reed-Solomon (d'ou le decodeur de relecture) ; `http.server` normalise `//chemin` ; lire un flux SSE avec `http.client` casse apres un timeout (socket brute dans les tests).
